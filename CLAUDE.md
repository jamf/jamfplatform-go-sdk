## Project

Go SDK for the Jamf Platform REST API
(`github.com/jamf/jamfplatform-go-sdk`). All types, methods and unit
tests are generated from OpenAPI spec files. OAuth2 client-credentials auth via
`golang.org/x/oauth2`.

## Commands

```bash
make ingest ZIP=path/to/gitops.zip   # Refresh testing/ source specs from a GitOps bundle
make permmap     # Refresh the committed snapshot of the published permissions map
make generate    # Regenerate Go code, tests, and published API specs from OpenAPI specs
make test        # Unit tests: go test -v -cover -count=1 -timeout=120s ./...
make testacc     # Acceptance tests (requires credentials, -tags acceptance): real API calls
make lint        # golangci-lint run ./...
go test -v -run TestFunctionName ./jamfplatform/
go vet -tags acceptance ./jamfplatform/   # after ANY generator change that alters a type
```

## Architecture

### Code generation

Everything under `jamfplatform/` except `client.go` is generated by
`tools/generate/` from the OpenAPI specs in `testing/`. The generator uses
[kin-openapi](https://github.com/getkin/kin-openapi) and produces type structs
from `components/schemas` (only those reachable from whitelisted operations),
client methods, httptest-based unit tests, and filtered public specs in `api/`.

Operations are **whitelist-based** — only endpoints listed in
`tools/generate/config.json` are generated. To add one, add it to config and run
`make generate`. Compact syntax:

```json
{"op": "GET /v1/devices/{id}", "name": "GetDevice"}
{"op": "GET /v1/devices", "name": "ListDevices", "pagination": "hasNext", "params": ["sort:[]string", "filter"]}
```

CI enforces that generated output is current on every PR
(`git diff --exit-code -- jamfplatform/`).

**`testing/` is populated by `tools/generate/ingest` from one GitOps bundle, and
every spec is copied verbatim.** `make ingest ZIP=…` writes each archive member
byte for byte — no re-emission, no YAML-to-JSON conversion — so a bundle diff is
exactly the delta. That is not cosmetic: three specs shipped as re-emitted YAML
(the account trio, AI Governance, uem-connect) and each had to be repaired by
hand before its diffs became readable, because hundreds of lines of indentation
churn hide the change.

Verbatim copying is why **every `config.json` spec entry names a `.yaml` file**.
`loadSpec` dispatches on the extension, and the YAML branch is a strict
superset of the JSON one — it also strips external parameter `$ref`s
kin-openapi cannot resolve. `readJamfProAPIVersion` decodes with
`yaml.Unmarshal`, which reads both the verbatim YAML and the JSON `api/`
fallback.

**Privileges are checked against a third, independent oracle.**
`tools/generate/permissions-map.md` is a committed snapshot of developer.jamf.com's
published permissions map, and `TestScopedPrivilegesUseGAVocabulary` asserts all
generated `{capability}:{action}` identifiers against its parsed capability
tables. The specs are where the values come from and `_permissions/routes.yaml`
cannot corroborate them — it is generated from the same extensions, so its
agreement is tautological — whereas the published map is authored from the
gateway's capability model. It currently agrees on **every one**, including
the `account` privileges that no published spec carries, so
`permissionsMapExceptions` is empty. `make permmap` refreshes the snapshot; a
new capability upstream makes the test fail, which is the notification to
refresh, not an accusation. Mechanism, the two guards that keep the parse
honest, and why the *path* dimension is deliberately not checked:
[docs/STYLE.md](docs/STYLE.md#required-privileges).

The ingest command also records `testing/.ingest-manifest.json` — which build each
spec and each `_permissions` file came from, plus the hash of the bytes written
— so a later run reports `unchanged (since vNNNN)` rather than merely
"differs", and the holds below are machine-checkable rather than prose only.

Every key config accepts, with its current usage count and the traps attached to
it, is inventoried in
[docs/STYLE.md](docs/STYLE.md#config-key-inventory); the mechanisms behind the
non-obvious ones are in the section after it. `tools/generate/config.go` is the
authority — its struct comments carry the reasoning for each field.

**`testing/` is gitignored and the generator falls back to `api/`.** So a stale
local spec regenerates the tree *backwards*. When checking a generator change for
CI parity, force the fallback path (a scratch root of symlinks with no `testing/`,
or a repo copy with it removed) so a local spec cannot contaminate the diff.

**Do that for a whitelist change too, not just a generator change.** `api/` is
pruned of unreachable schemas and `testing/` is not, so removing an operation can
leave a schema present-but-unreachable in `testing/` and absent in `api/` — and
`hoistInlineObjects` names its nested types after whichever parent it sees first.
That once produced 31 type renames visible only in the CI path.
`pruneUnreferencedSchemas` now runs between
`applyPostSymmetry` and `hoistInlineObjects` on both paths so the two inputs are
identical by construction — see
[docs/STYLE.md](docs/STYLE.md#schema-handling) for why neither side of that
ordering is negotiable.

**The generator prunes files it did not write.** Because generation is
whitelist-driven, removing an operation stops a file being emitted but does not
remove the one already on disk — and that file keeps compiling against types
`types.go` no longer declares, which CI's `git diff --exit-code` cannot catch
because an untouched file produces no diff.
`writeGenerated` records every write and `pruneStale` deletes any `.go` file in a
written-to directory that this run did not write **and** that carries the
`// Code generated by tools/generate; DO NOT EDIT.` marker; `pruneStaleSpecs` does
the same for `api/*.json`, but only when `publishSpecs` actually ran. Three
guards, each load-bearing:

- **The marker authorizes the deletion, not the write log.** The log finds
  candidates; the marker decides. So the worst a tracking bug can do is delete
  something the same run regenerates. `client.go` and the `acc_*_test.go` suite
  live in a directory the generator writes into and are structurally safe.
- **A run that wrote nothing prunes nothing**, so a failed or misconfigured
  generate cannot empty the tree.
- **Specs are gated on publishing having run.** JSON carries no marker, and in CI
  `testing/` is absent, publishing is skipped, and `api/` is the generator's own
  input — pruning there would delete the source.

Any new write must go through `writeGenerated`; a write that bypasses it looks
stale and gets deleted on the next run.

### Two-layer design

- **`jamfplatform/`** — exported package. Generated types and methods, plus the
  handwritten `Client`. Methods call `c.transport.Do` / `DoExpect` /
  `DoWithContentType`.
- **`internal/client/`** — HTTP transport: OAuth2, marshaling, error handling,
  logging, `ListAllPages[T]`, `ListAllCursorPages[T]`, `PollUntil`, RSQL building.

**`appleschemas/` is handwritten, plus a generated table from a non-OpenAPI
upstream** (Apple's `apple/device-management`; `make apple-schemas`, never part
of `make generate`). It is outside `jamfplatform/` on purpose: that tree is
generated and pruned. See
[docs/STYLE.md](docs/STYLE.md#apple-schemas-generator).

**`appstore/` is handwritten too, and its upstream is not a Jamf service** (Apple's
unauthenticated content-metadata lookup). It shares nothing with the transport —
no credentials, no scope header, no retries — and is standard library only. Its
wire law is in the package godoc and
[WIRE-FACTS.md](docs/WIRE-FACTS.md#apple-app-store-lookup-appstore--not-a-jamf-service).

Transport entry points: `Do(ctx, method, path, body, result)` expects 200;
`DoExpect(..., expectedStatus, result)` expects a specific status;
`DoWithContentType(..., contentType, expectedStatus, result)` overrides
Content-Type; `DoWithOptions(..., client.RequestOptions{…}, result)` is the
general form and the **only one that can carry request headers**.

**A PATCH body has no default Content-Type; the transport refuses one sent
without a type**, before any request goes out. The gateway's endpoints split
between `application/json` and `application/merge-patch+json` and each enforces
its own, so either default breaks half of them — the old merge-patch default
made every generic PATCH to `devices` and `device-groups` a 400. Every spec's
declared type was wire-checked correct, and every generated method passes it, so
only a generic-transport caller can reach the refusal. Evidence:
[WIRE-FACTS.md](docs/WIRE-FACTS.md#patch-content-types-2026-10-04).

`RequestOptions` exists because the per-request dimensions are independent —
expected status, Content-Type, extra headers, retry opt-out — so a wrapper per
combination doubles the surface each time one is added. The named methods above
are shorthands, and a generated method keeps whichever it already used; only
the four operations with `headerParams` route through `DoWithOptions`, which is
what holds a regenerated diff to the operations that actually gained a header.

## URLs, scope and auth

### Path construction

All paths are `/{namespace}/{version}/{resource}`, built by
`Transport.APIPrefix(namespace, version)`. An empty version collapses that segment
(proclassic, Pro preview paths).

**There is no `/api` segment, and the base URL must be the gateway root:
`https://{region}.api.jamfcloud.com`.** The GA gateway mounts every namespace at
the root and answers `404 page not found` for anything under `/api`; the retired
`apigw.jamf.com` required it and is gone. A base URL carrying a path prefix cannot
work and **the failure lands on authentication**, because `TokenURL` is
`baseURL + "/auth/token"` — which is why `annotateTokenError` special-cases 404 on
the token exchange and names the base URL.

**`servers` is never the authority — the gateway is.** The SDK never reads it, so
specs are ingested verbatim and any disagreement is reported upstream; **do not
patch the transport to follow them.** Every `external/` spec now declares the
gateway root with no `/api` segment, and since v2219 the stage and dev trees
match that shape too. A stage-sourced `servers` block still must not be
followed: the host is non-production, and its `(STAGE)` title would leak into
`api/*.json`.

### The tenant is a request header, not a path segment

`WithTenantID` records a scope and `setScopeHeader` stamps `X-Tenant-Id` on every
request, including the multipart path. The old `/tenant/{tenantId}` path form was
**deleted** rather than kept behind a flag: a second code path that nothing
exercises is how URL-shape bugs survive unnoticed. The generated httptest handlers
assert the header form, and `TestTransportAPIPrefix` asserts a tenant ID can never
reach a URL.

`stripTenantPathSegment` removes a leading `/tenant/{tenantId}` from any spec path
that still carries one, so a path-scoped spec still generates a correct GA URL.
**Re-ingesting a header-form spec without stripping the segment from its `"op"`
strings in the same change fails hard** with `path %s not found in spec` — which is
the good outcome, since the alternative is silence.

`ScopeKind` carries which header a scope travels in: `ScopeTenant` →
`X-Tenant-Id`, `ScopeEnvironment` → `X-Environment-Id`. **Organization scope has
no header at all** — the gateway resolves it from the token.

**Environment is the scope to prefer; tenant is legacy.** An environment groups a
customer's tenants and Jamf intends new integrations to be environment-scoped.
Tenant scope stays supported, but should not be the default choice.

**The two options are alternatives, not aliases: the header must match the
credential.** Crossing them over is `403 OWNERSHIP_FORBIDDEN` even within one
customer. A client carries exactly one scope, and setting both is a configuration
mistake rather than a combination: **environment takes precedence whichever order
the options are passed in**, because a client built from an environment-scoped
credential cannot use a tenant header anyway. `WithEnvironmentID`'s godoc is the
authority.

**Consumers read the scope back via `Client.Scope() (ScopeKind, string)`**, which is
the only scope accessor on the exported client. The transport's `TenantID()` is still
reachable through `Client.Transport()` but is a **partial view** — it returns `""` for
both environment and organization scope, so it cannot distinguish them and **must not
be used to infer the scope**. A zero kind with an empty ID is the organization case,
which a caller switching on the kind has to handle.

Security Cloud is a separate product with its own tenant identifier, but it travels
in the same `X-Tenant-Id` header as Jamf Pro's, so it is supplied with plain
`WithTenantID`. The per-namespace override that used to carry it —
`WithSecurityCloudTenantID` / `WithNamespaceTenantID` — **was deleted with the move to
header scoping and exists nowhere in the code**; a client reaches exactly one
product's Security Cloud tenant at a time. An environment credential also reaches
`/securitycloud` (wire-verified 2026-09-03), which is what lets the acceptance suite
fall back to one.

### Custom request headers (reverse-proxy support)

`WithHeaders(http.Header)` adds headers to every request **including the OAuth2
token exchange**, and `WithAuthorizationHeaderName(name)` moves the bearer to a
header of the caller's choosing. Both exist for consumers behind a corporate
reverse proxy that authenticates callers itself.

**Prefer these over `WithHTTPClient` for that purpose.** Supplying a client
replaces `newTunedTransport` and silently discards
`Proxy: http.ProxyFromEnvironment`, the per-phase timeouts,
`MaxIdleConnsPerHost: 10` (matched to Terraform's default parallelism) and the
1 MiB write buffer package upload depends on. Nothing fails — throughput and
env-proxy support just go. `TestWithHeaders_PreservesTunedTransport` pins it.

Three details that are not guessable:

- **The wrapper installs on `baseClient.Transport`, below `oauth2.Transport`.**
  That is what lets it see and move the bearer oauth2 already wrote, and what gets
  the headers onto the token exchange. Wrapping the OAuth2 client instead passes an
  API-only assertion while leaving authentication unproxied.
  `installHeaderTransport` must also **rebuild** the OAuth2 wrapper afterwards:
  `oauth2.NewClient` captures the base transport by value. `SetHTTPClient` and
  `SetUserAgent` both re-run it, since each replaces `baseClient` outright.
- **Relocation matches on the `Bearer ` scheme, not the request phase** — both
  phases write to `Authorization`, and moving the `Basic` client credential sends
  it to a header the token endpoint does not read.
- **A caller-supplied `Authorization` flips the token exchange to
  `AuthStyleInParams`.** Wire-verified that the token endpoint accepts body-form
  client credentials.

The scope headers (`X-Tenant-Id`, `X-Environment-Id`) are **rejected** by
`WithHeaders` and as a relocation target, and the rejection logged: a wrong value
gives the same `403 OWNERSHIP_FORBIDDEN` a mismatched credential does, so a silent
override is close to undiagnosable. `WithAuthorizationHeaderName` also refuses
`Authorization` itself, since the relocation sets the target then deletes the
source — the same key, so every call would 401. `reservedHeaders` is keyed through
`http.CanonicalHeaderKey` so a spelling Go canonicalises differently fails a test
rather than failing open. `User-Agent` is deliberately **not** protected
(`userAgentTransport` sits above and wins); neither is `Cookie`, because a proxy
may require one — but headers *replace* rather than merge and `http.Client` writes
the jar's `Cookie` before the transport chain runs, so a caller-supplied `Cookie`
displaces Jamf Cloud's sticky-session pin. The godoc says so.

### Request lifetime and retries

**The SDK sets no `http.Client.Timeout` and no default `ResponseHeaderTimeout`;
the caller's context is the request deadline.** Both would fire whatever context
was passed and so override it — a Terraform `update = "10m"` was cut off at 60s.
`WithResponseHeaderTimeout` is the opt-in for a flat ceiling, a logged no-op under
`WithHTTPClient`. The guard against a silently dead connection is an HTTP/2 health
check on the tuned transport (30s + 15s), which cannot interrupt a slow response.
Every consumer is expected to pass a context with a deadline.

**Multipart uploads go over HTTP/1.1, chunked, with no declared `Content-Length`**
— every `DoMultipart` method, unconditionally. CloudFront's 64 KiB per-stream h2
window caps an h2 upload near 4 MiB/s, and a declared length lowered the ceiling
of a large upload on this gateway; it is a measured workaround, not best practice,
and not a claim that very large uploads are safe, so revisit it if the gateway
changes. Transport-error retries of an upload are bounded at one, since each
re-sends the whole file. Rationale, the decisions that look like
omissions (no threshold, no opt-out), and the `WithHTTPClient` limitation are in
[docs/STYLE.md](docs/STYLE.md#multipart-uploads-http11-no-declared-length-no-threshold-no-opt-out).

**A transport error is retried freely only while the request never finished being
written.** After that, only an idempotent method (GET/HEAD/PUT/DELETE) and never a
timeout, because `retryablehttp`'s default would replay a POST after a connection
reset the server had already acted on. The state travels in the request context
(`sendState`), not the error, so it survives `http.Client.Timeout` replacing the
error. Mechanism, the one known race, and the OAuth refresh — the one call the
context cannot reach — are in
[docs/STYLE.md](docs/STYLE.md#timeouts-and-retries).

**The gateway rate-limits per client ID, and the SDK slows down before the
limit rather than after it.** `requestThrottle` spreads the requests
`x-ratelimit-remaining` says are left across the time to `x-ratelimit-reset`
— milliseconds apart with the budget nearly full, so concurrency is untouched,
and waiting for the window at an estimate of 0. The estimate subtracts every
request started after the one whose response carried it, which is what covers
the client's own in-flight requests. **A gateway 429 holds every goroutine
until the window ends**: the published guidance's first step is to stop
sending, and a limiter that counts refused requests would keep refusing a
client whose other goroutines kept going. A success reporting `remaining: 0`
is ignored, so a limiter that reports 0 on every response cannot stall the
client.

**The budget gate alone does not hold an interval-0 client under the limit**,
so a ceiling sits beside it: once `x-ratelimit-limit` is known, starts are
`(1s + 1s/4) / limit` apart — 80 a second at today's 100. Reset and `Date` are
whole seconds, so for most of the window the time to reset reads 0 and there
is nothing to spread across; and `remaining` is not the global budget. **The
gates combine as the stricter gap, never the sum** — each is measured from the
same base. The 100ms `WithMinRequestInterval` default is not a rate-limit
control: it came in with the removal of the eventual-consistency retry, as a
write-to-read cushion, and the ceiling works without it.

Tyk's 429 has no `Retry-After`, so `jamfBackoff` retries the refused request
after `x-ratelimit-reset`, measured against the response's `Date`, plus jitter
— **only when `x-ratelimit-remaining` is `0`**, because the gateway stamps the
same headers on a service's own 429 (the blueprints report), whose reset is
meaningless and which needs the exponential backoff instead. **Never encode
the limit** — it is gateway configuration that changes without notice and is
read off `x-ratelimit-limit`. The one-second window is the single assumption,
and only because the platform documentation publishes it.

Evidence: [WIRE-FACTS.md](docs/WIRE-FACTS.md#rate-limiting).

## Pagination

`ListAllPages[T]` takes a `fetchPage(ctx, page, pageSize)` callback. Four styles,
configured per operation: `hasNext`, `sizeCheck`, `totalCount`, and `cursor`.

**Raising a page size above the safe default is a silent-data-loss risk, not a
rejected request.** An oversized `page-size` is not always an error — some
endpoints just return fewer items than asked with HTTP 200 — and `ListAllPages`
computes each page's offset by multiplying the *requested* size, so page N+1 skips
the untransferred tail of page N with no error at any layer.

The page size is `defaultMaxPageSize(pkg, style)` unless overridden per operation
via `"maxPageSize"`, threaded through as an explicit argument, never a hardcoded
constant. **`pro` + `totalCount` → 2000; everything else → 100.** That scoping is
as narrow as the evidence: see
[WIRE-FACTS.md](docs/WIRE-FACTS.md#pagination) for the 33 operations verified at
2000, the two pro operations deliberately excluded, and `devices/v1`, which
*hard-rejects* above 1000 rather than clamping.

**Configuring `pagination` for an endpoint that ignores the params is a
duplication bug**, not a truncation one: `hasNext = (page+1)*pageSize < totalCount`
cannot detect a server that always returns everything, so it loops and
concatenates the same list. Two Security Cloud ops were configured that way off
their envelope shape alone. **Probe before trusting a `{totalCount, results}`
envelope.**

`cursor` pagination is configured with `resultsField` (the envelope key holding
the array) plus `cursorField` (default `nextCursor`) and `cursorParam` (default
`cursor`); `ListAllCursorPages[T]`'s callback takes the cursor for the page to
fetch, empty on the first call. audit is the only user — `ListAuditEvents` over
`{items, nextCursor}` and `GetResourceLineage` over `{transactions, nextCursor}`.

It cannot truncate the way the offset styles can, which is why it exists rather
than forcing a cursor endpoint into `totalCount`: the next page's position comes
from the server's own cursor, not an offset the client multiplies out, so a
clamped `page-size` costs extra round trips and nothing else. Two behaviours to preserve: **an
empty page does not end the walk** — only an absent cursor does, since a page can
legitimately have every row filtered out server-side while later rows remain
reachable — and **a repeated cursor is returned as an error**, because otherwise a
misbehaving server hangs the caller with no error. Both are pinned in
`internal/client/pagination_test.go`, and the generated stub serves *two* pages so
a method that ignores the cursor fails.

### Unpaginated lists decide their shape from the body

`unwrapResults` (6 operations) generates a call to `client.UnwrapResults[T]`,
which reads the first non-space byte and accepts **either** the
`{totalCount, results}` envelope the spec declares **or** a bare JSON array.

**That is a fix for a shipped outage, not defensive padding.** The four account
list endpoints served a bare array until 2026-09-01 and the envelope after, and
every account list method then failed on every call. **A generated method that
hardcodes one shape cannot be tested for the other** — the httptest stub serves
whatever the method assumed — so the first fix, swapping the
`responseType: "[]T"` override for `unwrapResults`, was symmetric to the bug and
would have broken identically if the server went back. Don't reintroduce a
shape assumption in either direction.

Nothing downstream changed: the signatures stay `([]T, error)`, and
`terraform-provider-jamfplatform` calls `ListDeviceGroupMembers` from five
places unedited. The detection that tolerance removed lives in the acceptance
suite instead — `assertListBodyShape` pins each endpoint's current shape, so a
flip fails a wire test rather than a consumer's `terraform plan`, and **every
`unwrapResults` operation should have one**. Mechanism and the empty-vs-error
table: [docs/STYLE.md](docs/STYLE.md#config-key-inventory); observed shapes:
[WIRE-FACTS.md](docs/WIRE-FACTS.md#re-probed-2026-09-01-three-of-the-recorded-faults-have-flipped-and-two-of-them-broke-the-sdk).

## Working with specs

### Ingesting a new GitOps bundle

The procedure is the `ingest-specs` skill; what follows is the position and the
reasoning behind it.

**Every spec the SDK carries is published to `external/`, so an ingest is one
command.**

```bash
make ingest ZIP=~/Downloads/jamf-platform-apis-gitops-vNNNN-*.zip INGEST_FLAGS=-dry-run
make ingest ZIP=~/Downloads/jamf-platform-apis-gitops-vNNNN-*.zip
make generate
```

**Start with the dry run, because a build number advancing is not evidence of a
spec change.** Builds can be pure pipeline re-runs (four so far) and two can
land the same day. The report prints the archive's SHA-256 and, per spec,
`unchanged (since vNNNN)` / `updated (was vNNNN)` / `new` against the ingest
manifest.

Three conditions the command **refuses** rather than reports, each because the
silent version of the failure has happened here:

- **An `external/` family that neither the provenance table nor
  `knownUnmapped` accounts for.** A newly published API appears in no diff of
  the specs already carried, which makes it the easiest thing in a build to
  miss.
- **An `info.title` that does not match the row's assertion**, which is the
  "map by title, not by directory name" rule made executable. Directory names
  are not stable, and a name-keyed match that finds nothing reports "no
  changes" rather than failing. Titles are matched **longest fragment wins**
  (`titleOwner`), because fragments nest: jpapi's `Jamf Pro` is a substring of
  capi's `Jamf Pro Classic`.
- **A selected family absent from the archive.** A *held* row absent is
  tolerated, since reconstructing an older build legitimately predates a
  family's publication.

**Held specs are skipped and their reason printed on every run**, so a hold
cannot rot unnoticed; `-only <dest>` or `-include-held` takes one, and the
position section below must move in the same change.

**A `-only` run reports `_permissions/{routes,scopes}.yaml` but writes
neither.** Those two files are not spec-scoped, so a narrowed run would
otherwise rewind the whole privilege oracle to that archive's build. **A full
run is what refreshes the oracle.**

**Never ingest from `internal/dev`.** It carries a per-spec `x-generated` block,
so *every* spec reports as changed. Comparing operation *sets* across
environments is what it is good for — that is how a prod-only publishing filter
was caught. `internal/stage` declares a stage host and an `(STAGE)` title that
would leak into `api/*.json`.

**Never fall back to the spec repository's own per-team directories.** They
carry no version prefix and no servers, so the methods they produce have URLs
the gateway rejects — invisible until called. **A spec absent from the build is
a spec the SDK does not cover**, and the gap gets reported upstream.

After ingesting, **diff the operation set, the schemas, `required`, enums,
privileges *and* config's own overrides** — structurally, with prose stripped.
`expectedStatus` and `responseType` have no tripwire, and silent overrides
going redundant has happened repeatedly. Then **wire-probe every behavioural
claim**, with a control in the same invocation: builds have repeatedly shipped
specs *ahead of the server*.

**Record the build in [docs/INGEST-HISTORY.md](docs/INGEST-HISTORY.md), not
here.** This file carries the position and the rules; the history file carries
what each build did and how it was verified. A build that changes a standing
fact changes the relevant section here in the same commit.

### The privilege and scope oracles

`_permissions/routes.yaml` + `scopes.yaml` are exactly self-consistent, which is
what makes them usable to adjudicate a spec's privileges. **But `routes.yaml` is
generated from the specs' own `x-required-privileges`, so it cannot corroborate
them** — and absence from it causes no refusal. The independent checks are the
published permissions map (above) and the gateway's authorization policy; see
[WIRE-FACTS.md](docs/WIRE-FACTS.md#where-the-per-path-allowlist-lives).

**`MethodPrivileges` carries `Scopes []ScopeKind` beside `Scoped`**, so one
registry lookup answers both "what privileges" and "what scope". The two are
opposites and the godoc says so: `Scoped` is a conjunction (grant all of
these), `Scopes` an alternatives set (a client carries exactly one scope).

- **It is per-method although scope is declared per-spec**, because two specs
  in one package can disagree — `securitycloud` did while one of its specs was
  held.
- **`ScopesSource` records provenance** — `"spec"` or `"config-override"` —
  because the account trio's whole scope declaration comes from
  `config.scopeTypes`.
- **`ScopeOrganization` is a named zero value.** There is still no
  `WithOrganizationID`, but a registry has to *name* the scope; an empty
  `Scopes` would be indistinguishable from a spec that declared nothing.
- **An empty scope set is unreachable by construction.** `resolveScopeTypes`
  fails generation on a spec declaring no `x-scope-types` without an override,
  on an unknown kind, and on an override that has become redundant **or** that
  omits something the spec now declares. `TestEveryConfiguredSpecResolvesAScope`
  walks every spec.
- **The registry reports the spec's claim, which is stricter than the gateway
  for the Platform APIs** — see the disagreements table below. The
  `MethodPrivileges` godoc carries that caveat.

### Hard rules

- **Never modify the specs under `testing/`.** They are source-of-truth mirrors and
  must round-trip upstream changes. Fix quirks at the generator level.
- **Never hand-edit generated files**, and **never add handwritten code to a
  generated sub-package** — make the generator emit it. The prune step deletes
  such a file on the next run.
- **Endpoint versions are additive — but the spec wins when it drops a
  path.** Retain every version the spec still declares, side by side, so
  consumers get a migration window; a version goes when the spec removes it.
  Never remove one merely because a successor appeared. When the spec drops a
  path the wire still serves, follow the spec and record the disagreement —
  following it is the decision, not evidence that the server agrees.
- **Hold a spec only where following it would cost a capability outright**, and
  mirror the change in config where it would not; say which. A hold is a spec
  pinned at an older build with its reason in the ingest tool's `specs` row.
- **A `// Deprecated:` marker must never ship without its successor whitelisted
  alongside it.** `staticcheck`'s SA1019 is on by default, so deprecating a surface
  with nothing to migrate to turns every consumer's build red. Broken
  deliberately once, on instruction (`GetActivationCode`); the rule stands. The
  tool for this case is a hold, and a hold is cheap exactly when the offending
  flag is the build's only change.
- **Local spec repairs are self-expiring.** `schemaCreations` panics if the name
  reappears — except where it holds a *wire shape* under a new name, which never
  reappears: there a `schemaPatchesRequireAbsent` path on the *declared* schema,
  one that resolves only once the spec declares the wire shape, is the expiry,
  and where the spec declares no body at all nothing can be (the post-ingest
  `responseType` diff is the check); a `schemaPatches` entry that *supplies* a missing property needs a
  `schemaPatchesRequireAbsent` line or it shadows the real one forever;
  `enumAdditions` panics on a value the spec now declares; `requiredPrivileges`
  fails generation once the operation declares `x-required-privileges`;
  `propertyRenames` panics once the spec declares the target; `docNotes` and
  `methodNotes` fail when they name nothing emitted. Neither of the first two
  catches a re-typed root. **A generate that fails with one of these is the spec
  being repaired** — delete the entry.
- **A generated field may never be a bare `any`.** `validateNoUntypedFields`
  fails generation on `any` or `*any`: it means the generator met a construct it
  has no branch for, producing a field that type-checks nothing and decodes
  anything. **Do not widen the check to make a spec pass** — teach the generator
  the construct. `map[string]any` and `[]any` stay legal, which is exactly why
  the next two rules exist.
- **A type that cannot express the payload is the recurring defect, and the
  tell is always a consumer, never a test.** Four shapes so far, each now
  handled: a discriminator-less `oneOf` over `$ref`s (typed union when
  request-only, merge otherwise); a `oneOf` whose `discriminator` the spec forgot
  (`inferDiscriminator`, strictly, never written into `api/`); an array whose
  items are an inline `oneOf` (hoisted, then built as a union — `[]any` before);
  and a pure `additionalProperties` schema (a map alias — `= string` before,
  through the template's enum branch). Content-addressed discriminator keys
  (`com.jamf.ddm.*`) are refused **only on an envelope**, which keeps
  `Component` a struct with `Configuration json.RawMessage`, the shape
  `terraform-provider-jamfplatform` is built on. Mechanisms:
  [docs/STYLE.md](docs/STYLE.md#schema-handling).
- **A store that echoes its writer's JSON is a decode problem, not a spec
  problem — fix it in the decode and leave the field types alone.** blueprints
  stores a component `configuration` as its writer sent it, and the Jamf Pro UI
  writes numbers as strings. `config.lenientScalarRoots` names the `Component`
  union and the generator emits tolerant `UnmarshalJSON` methods across its
  subtree, with **zero change to any field type, signature, marshalled body or
  `api/*.json`**. Do **not** reach for this for a spec/wire *type* disagreement
  — that is `fieldTypeOverrides` or a report upstream.
  `TestAcceptance_Blueprint_UIWrittenScalarsDecode` asserts the quoted form
  still arrives, so it fails the day the mechanism can be deleted. Mechanism:
  [docs/STYLE.md](docs/STYLE.md#lenient-scalar-decoding).
- **A shared schema's optional scalars can change pointer-ness with no diff in
  their own schema**, because `needsPtr` follows request/response reachability.
  Not a generator bug, and **not** to be fixed by forcing one direction: that
  pointer-ises hundreds of fields across every package. Detail:
  [docs/STYLE.md](docs/STYLE.md#a-shared-schemas-optionality-follows-its-requestresponse-reachability).
- **Summary state prefixes reach Go.** The operation `summary` is the method
  comment, so upstream prefixing it (`Preview - `, `Deprecated - `) breaks
  godoc on a structurally nil diff. The strips gate on the structured field
  (`x-preview`, `deprecated: true`), never the prose, and `api/` keeps
  upstream's text verbatim. A test fails any generated comment carrying a
  lowercased state prefix inside its verb phrase.
- Full detail on every mechanism: [docs/STYLE.md](docs/STYLE.md#config-mechanisms).

## Verifying against the live API

**Probe the wire and quote the payload; never conclude from a spec diff.** The
standard for anything recorded as fact:

- **A known-good control in the same invocation.** Tokens live 900 seconds, and a
  rejected token gives the same plain-text `401 Authentication failed` as a
  credential with no policy for the api-product. Probing has been misreported
  from a cached expired token, from a broken shell helper, and from a helper
  that clobbered its caller's header array — each caught only by a control.
- **Repeat a routing probe, and read which layer answered.** A plain-text
  `404 page not found` is the gateway router (namespace not mounted; runs
  before authorization, so no grant changes it). A repeated
  `403 BAD_PERMISSIONS` is an unrouted path in a mounted namespace. A JSON 404
  or 4xx with a service `code` means the request reached the service.
- **Two credentials, not two paths, to classify a 403.** A 403 that varies by
  credential is a capability grant; one constant across credentials is a missing
  authorization rule.
- **Use the right credential set.** A pro credential answers 403 on every Security
  Cloud path, indistinguishable from an unrouted one; an environment with no
  Security Cloud tenant answers `404 TENANT_NOT_FOUND`.
- **Exploit validation ordering to probe safely, but establish it per
  operation.** Where body validation precedes resource resolution, a request
  against a nonexistent id exercises every field constraint and creates
  nothing. A body that fails to parse masks every field check.
- **A null-skipping sweep proves nothing.** A field mismatch hid behind an
  all-null column across five sampled rows and failed on row 31 of a larger
  sample.
- **SDK-mediated observation is not wire truth.** Go adds
  `Accept-Encoding: gzip` unasked, and that nulled `href` on every Security Cloud
  create for weeks while curl saw it fine. When curl and the SDK disagree, diff the
  requests.
- **Keep probe volume low against an edge block.** ~150 probe requests during one
  WAF investigation triggered an IP blocklist, causing a second, broader outage.
- **Track everything a probe creates and delete it before finishing**, then
  re-list. Where a create cannot be undone, create exactly one.
- **Redact the payload before committing it.** Tenant, domain, person and
  identity-provider identifiers go out as placeholders — the same placeholder for
  the same real value everywhere; the crosswalk lives in the untracked
  `docs/local/internal-provenance.local.md`.

Layer-by-layer diagnosis of a refusal, per-package findings and the full evidence:
[docs/WIRE-FACTS.md](docs/WIRE-FACTS.md).

## Conventions

- Options pattern for client configuration: `WithTenantID`, `WithEnvironmentID`,
  `WithUserAgent`, `WithHTTPClient`, `WithLogger`, `WithFileTokenCache`,
  `WithFileCookieJar`, `WithHeaders`, `WithAuthorizationHeaderName`.
- Generated types use spec schema names directly.
- `url.PathEscape` for path parameters, `url.QueryEscape` for query parameters.
- Error wrapping: `fmt.Errorf("MethodName(%s): %w", id, err)`.
- Resolvers and Apply methods are **declared entirely in `config.json`** — never
  hand-coded. Modes and keys: [docs/STYLE.md](docs/STYLE.md#nameid-resolvers).
- **Before every commit**, run `go fmt ./...` and `go fix ./...`, **and
  `go fix -tags acceptance ./jamfplatform/...`**; any diff they produce belongs
  with the functional change, not a follow-up commit. An untagged `go fix`
  cannot see the build-tagged acceptance files.
- **Conventional commits, for every commit and the PR title** —
  `feat(generate): ingest GitOps vNNNN, and …`, `fix(generate): …`,
  `fix(acceptance): …`, `docs: …`. A removed method already on `main` is `!`
  plus a `BREAKING CHANGE:` footer naming it. Each commit builds and tests on
  its own.
- **Every new generated method gets an acceptance test**, and **never silently
  tolerate a real error to make one pass** — no `>= 400 && < 500` escape hatches.
  A permanent 5xx is asserted, never skipped with `skipOnServerError`: a skipping
  test can never report the fix. Policy: [docs/STYLE.md](docs/STYLE.md#acceptance-tests).
- **`go vet -tags acceptance ./jamfplatform/` after any change that alters a
  type.** The suite is build-tagged, so `make test` and CI never compile it and a
  signature change breaks it silently.
- **Downstream breakage is reported, never migrated from here** — name the
  consumer files that break (`terraform-provider-jamfplatform`,
  `terraform-provider-jamfplatform-internal`, `jamf-cli-internal`).
